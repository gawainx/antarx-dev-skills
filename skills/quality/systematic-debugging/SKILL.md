# 系统化调试

## 1. 建立故障事实

阅读错误、相关代码和已有日志，区分期望行为与实际行为，定位受影响路径及相关近期变更。能复现时记录最小触发条件；间歇性或环境受限的问题使用日志、事件时序、失败频率和环境差异取证，不把稳定复现作为继续调查的前提。

## 2. 检验原因

提出可证伪的原因假设，选择能区分候选原因的最小检查或实验。一次实验只改变必要变量，依据结果更新假设，不叠加未经验证的补丁。

只有现有证据不足时才增加诊断日志；只有存在相关参考实现时才比较，并聚焦可能影响故障的差异。错误信息和代码已足以定位简单问题时，直接验证该原因，不补做无关调查步骤。

## 3. 修复并验证

修复已由证据支持的原因，保留其他已有改动。能自动断言的行为优先建立最小回归测试并确认修复前失败、修复后通过；无法自动复现时使用对应日志、集成检查或可重复的操作验证，说明覆盖限制。

运行受影响范围的检查。新增修改、失败或未排除的风险需要时再扩大验证；已经通过且代码未变的检查不重复运行。

线上故障需要先恢复服务时，可在授权范围内执行有证据支持、可回退的缓解措施；分别报告恢复情况和未解决的根因，不把临时缓解宣称为根治。

## 4. 报告结果

说明故障原因、支持证据、修复内容及实际验证结果。仍无法确定原因时，列出已排除项和下一项能缩小范围的检查，不以“看起来正常”宣布修复。
