# 测试反模式

编写或修改使用测试替身的测试时，检查以下事项：

- 断言只验证 mock 节点存在或 mock 返回了预设值：改为断言被测组件产生的行为和结果。交互本身是契约时，可以断言调用参数和次数。
- mock 掩盖被测行为依赖的副作用：降低替换层级，或使用保留该契约的 fake，避免把需要验证的逻辑一起替换掉。
- 测试数据缺少被测路径及其下游实际读取的字段：依据真实接口和 schema 构造有效样例，并按需覆盖缺失字段，不盲目复制所有无关字段。
- 为测试添加与生产职责无关的清理接口：把测试专用操作留在测试工具中；真实资源生命周期接口仍由负责该资源的模块提供。
- mock 配置复杂到难以解释行为：考虑使用真实组件的集成测试，比较运行成本和可定位性后选择。

TDD 的执行顺序不能替代测试质量检查。测试必须能识别目标行为的错误，而不是仅随当前实现一起通过。
