# 测试驱动开发（TDD）

## 核心原则
先测试、后实现；没有红灯就没有有效绿灯。

## 标准循环
1. RED：先写一个能稳定失败的测试，且失败原因正确。
2. GREEN：做最小实现让测试通过，不顺带扩功能。
3. REFACTOR：在测试持续为绿的前提下清理结构。
4. 重复下一个最小行为。

## 关键要求
- 测试应小而单一、命名清晰、体现行为意图。
- 不允许先写实现再补测试来“证明正确”。
- 回归测试需验证红->绿链路，而非只看一次通过。
- 避免一次修太多点，保持可归因。

## 常见反模式
- “我先实现，最后统一补测”。
- “手工测过了就行”。
- “先把大块功能写完再拆测试”。

## 落地建议
- 每个失败测试只对应一个行为增量。
- 优先写最小可断言接口，不依赖脆弱细节。
- 重构只在绿灯下进行，不改行为。
