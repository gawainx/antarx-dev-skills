# 进度记录审计细则

## 仓库约定
- 优先读取 `AGENTS.md`、`CLAUDE.md`、`README.md`、设计文档、开发计划中关于进度文件路径、条目格式、需求编号、提交记录和推送规则的要求。
- 仓库约定优先于本技能默认规则。若两者冲突，采用仓库约定，并在最终回复中简要说明。
- 若仓库未指定路径，默认使用 `docs/PROGRESS.md`。

## 文件读取与定位
- 若进度文件存在，读取全文，识别写作风格、二级章节结构、最后一条记录中的提交哈希和已有需求编号。
- 若进度文件不存在，创建空文件，并基于当前提交状态生成总结。
- 若仓库使用需求编号，从用户输入、开发计划、设计文档、分支名、提交信息或相关文件名中识别 `requirement_id`。
- 若仓库使用需求编号但无法识别当前编号，停止记录并询问用户，禁止写入无编号条目。
- 若进度文件按 `## ` 二级章节组织记录，必须先确定目标章节；无法可靠确定时停止并询问用户。

## 内容规则
- 进度内容仅使用简体中文。
- `{content}` 必须是一段连续中文文本，不使用列表、编号、小标题或多段结构。
- 若当前上下文包含开发计划，需要在内容中补充开发计划文件名，例如 `docs/exec-plans/active/model_design.md`。
- 内容应像需求变更纪要，优先写做了什么需求、为什么这样做、关键边界是什么。
- 禁止记录通过的单元测试数量、编译结果、验证命令清单、同步状态或推送状态，除非这些信息本身就是需求决策或用户明确要求记录。

## 格式规则
- 默认条目格式：`- ({curr_git_head_hash:8}) : {curr_date_yyyy_mm_dd} {content}`。
- 使用需求编号时的默认条目格式：`- [{requirement_id}] ({curr_git_head_hash:8}) : {curr_date_yyyy_mm_dd} {content}`。
- 日期格式为 `YYYY.MM.dd`。
- 进度文件中的记录必须保持为 Markdown 一级列表，每条记录只能以 `- ` 开头。
- 禁止新增嵌套列表、编号列表、引用块、小标题或多级结构。
- 若现有内容不是一级列表，且仓库没有明确允许改写历史，只追加符合一级列表的新条目，并在最终回复中说明历史内容存在格式偏差。

## 哈希规则
- 执行收尾前，记进度文件最后一条记录中的哈希为 `hash1`。
- 若存在进度文件以外的未提交改动，必须先只提交这些改动，提交成功后获取该提交哈希，记为 `hash2`。
- 若只有进度文件改动或工作区已干净，将当前 `HEAD` 视为 `hash2`。
- 新记录中的哈希必须是 `hash2` 的前 8 位。
- 提交进度文件后，禁止再次修改进度记录，把哈希回填成进度提交自身的哈希。

## 插入与更新规则
- 若没有二级章节，新记录只能追加到文件末尾。
- 若存在目标二级章节，新记录只能追加到该章节末尾、下一个 `## ` 标题之前。
- 禁止为了按需求编号、提交哈希、文件名或主题分类而把新记录插入历史列表中间。
- 若仓库未使用需求编号，禁止修改或重排历史条目。
- 若仓库使用需求编号，相同需求编号只能产生一个条目；已存在时只允许改写该条目本身，并保留其他历史条目的原始顺序与内容。

## 提交规则
- 提交信息必须满足仓库 Conventional Commits 规则。
- 禁止空消息、无意义消息和 `git commit --amend`。
- 当工作区同时存在进度文件和其他文件改动时，必须拆成两个提交：第一个提交不包含进度文件，第二个提交只包含进度文件。
- 生成第一个提交前确认暂存区不包含进度文件。
- 生成第二个提交前确认暂存区只包含进度文件。

## 重试与防重
- 先构造完整候选条目字符串 `entry_line`，再执行去重检查，最后才允许写入。
- 若仓库未使用需求编号，追加前检查完整条目是否已存在；已存在时禁止再次追加。
- 若仓库使用需求编号，写入前检查 `requirement_id` 出现次数：0 次则追加，1 次则更新，超过 1 次则停止并要求人工合并重复记录。
- 若需要追加新条目，去重通过后重新定位文件末尾或目标章节末尾，禁止复用可能过期的插入行号。
- 若命令在“已写入但未提交”阶段失败，重试时必须先做同样的去重检查。

## 推送与结束校验
- 判断当前分支是否存在 upstream，且推送不会违反仓库约定或用户指令。
- 若可以推送，执行 `git push`。
- 若不能推送，在最终回复中说明原因。
- 结束前确认工作区干净。
- 确认进度记录路径、格式、位置、哈希正确。
- 确认当前需求编号只对应一个条目，或无需求编号时仅新增一条记录。
