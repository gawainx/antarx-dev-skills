# 更新 Codex Memory

使用这个技能回顾近期工作，判断哪些内容值得进入长期记忆，先检索已有笔记，再把小段、可审查的 Markdown 写入合适位置。

## 知识库路径

按以下顺序解析 memory 根目录：

1. 用户明确提供的路径。
2. shell 环境变量 `CODEX_MEMORY_DIR`。
3. 默认路径 `/Users/yat/notes/ClawNotes/CodexMemory`。

写入前必须验证所选路径存在，并且包含 `AGENTS.md`。如果不满足，停止并请用户先初始化 Codex Memory 或提供正确路径。

## 工作流程

1. 回顾已完成的开发或执行流程。
   - 提炼任务中学到的事实、已验证命令、稳定路径、决策、用户偏好、未闭环事项和可复用流程。
   - 区分事实和推断。
2. 判断候选内容是否有长期价值。
   - 只写入未来任务大概率会复用的信息。
   - 跳过低价值总结、临时过程记录和完整聊天记录。
3. 写入前先检索已有 memory。
   - 使用 `rg -n "<关键词>" <memory-root>` 检索具体项目名、命令名、文件名、决策或流程关键词。
   - 优先更新已有相关笔记。
   - 没有合适笔记时再新建。
4. 写入小段 Markdown。
   - 使用明确标题。
   - 包含日期、来源任务和适用范围。
   - 同时存在事实和推断时，分节记录。
   - 发现旧记忆过时时，不直接删除，标注 `已过时` 并说明原因。
5. 返回更新后的文件路径，供用户审查。

## 写入内容

只写入预计之后会再次用到的长期知识：

- 用户长期偏好、明确边界、反复强调的工作方式。
- 项目的稳定路径、关键命令、环境差异、发布流程。
- 已验证过的故障原因、修复方式、排查顺序。
- 重要决策及其原因。
- 跨项目待办、悬而未决的问题。
- 可复用的文章结构、脚本流程、研究模板、提示词。

## 禁止写入

不要写入：

- 完整聊天记录、流水账、临时情绪、一次性中间过程。
- Cookie、Token、API Key、密码、验证码、身份证号、银行卡、私密联系方式、第三方账号凭证、日志里的敏感值。
- 为了“显得有记忆”而写的低价值总结。

## 目录选择

- 项目相关长期事实：`Projects/`
- 用户、合作方、角色偏好：`Roles/`
- 可复用流程、命令、检查清单、提示词：`Workflows/`
- 重要选择、取舍和原因：`Decisions/`
- 可复用模板或表达方式：`Resources/`
- 跨项目未闭环事项：`TODO.md`
- Agent 后续跟踪事项：`agent/open-loops.md`

## 写作风格

- 默认使用简体中文；如果用户当前对话使用其他语言，则技能内容、记忆内容和输出语言跟随用户对话语言。
- 追加到已有笔记时使用带日期的小节。
- 每次更新保持足够小，方便 diff 审查。
- 使用具体名称、路径、命令或适用条件。
- 避免把猜测沉淀成规则。

## 最终回复

写入后说明：

- 是否更新了 memory。
- 变更了哪些文件路径。
- 用一句话概括记录了什么。
