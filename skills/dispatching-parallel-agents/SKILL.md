# 并行派发子代理

## 核心原则
一个独立问题域对应一个代理，并发处理，最后统一集成。

## 何时使用
- 多个失败分布在不同测试文件/子系统，根因明显独立。
- 每个问题无需依赖其他问题结论即可推进。
- 代理之间不会争用同一状态或同一改动面。

不适用：
- 问题强相关（修一个可能联动修其他）。
- 必须先建立全局系统理解。
- 会发生文件冲突或共享资源干扰。

## 执行模式
1. 先按问题域分组（按文件、子系统、错误簇）。
2. 每个代理只给单一清晰目标与约束。
3. 并行派发。
4. 回收结果后做人审：冲突检查、全量验证、再集成。

## 任务提示词要求
- 聚焦：只给一个问题域。
- 自洽：给足上下文、错误信息、测试名。
- 约束明确：是否允许改生产代码、是否只改测试。
- 输出明确：必须返回“根因 + 改动摘要 + 验证结果”。

## 常见错误
- 任务过大导致代理发散。
- 只说“修 race”不给定位信息。
- 不设约束导致大范围重构。
- 不做最终统一验证。

## 验证闭环
1. 审阅每个代理摘要。
2. 检查改动冲突与覆盖面。
3. 跑全量或目标回归。
4. spot check 防系统性误修。
