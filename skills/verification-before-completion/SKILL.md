# 完成前验证

## 核心原则
先证据，后结论。

## 铁律
没有“新鲜验证证据”，不得声称完成。

## 闸门步骤
在任何完成性表述前必须执行：
1. 确定可证明结论的命令。
2. 运行完整命令（本次会话、完整输出）。
3. 读取输出、退出码、失败计数。
4. 判断证据是否支持结论。
5. 仅在支持时给出成功表述，并附证据。

## 常见误区
- “应该可以了”。
- 只看部分检查结果外推出“全部通过”。
- 直接信任子代理“已成功”的口头回报。

## 典型映射
- 测试通过：必须有测试命令 0 失败输出。
- 构建成功：必须有构建命令 exit 0。
- bug 修复：必须复测原症状通过。
- 满足需求：必须逐条对照清单。

## 适用时机
- 提交前、PR 前、阶段结束前。
- 从一个任务切换到下一个任务前。
- 任何表达“好了/完成了/通过了”之前。
